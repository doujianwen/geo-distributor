```
│   └── www/          # 营销官网
├── packages/
│   ├── lib/          # 核心逻辑（DB schema, providers, mentions, reports）
│   ├── ui/           # 共享 UI 组件
│   ├── config/       # 配置管理
│   └── api-spec/     # OpenAPI 规范
└── docker/           # Docker 部署配置
```

### 2.2 核心数据流

```
Brand (组织)
  ├── Prompt (采集任务)
  │     └── PromptRun (单次运行结果)  ← 对应 Observation
  │           └── Citation (引用来源)  ← 对应 Citation
  ├── Competitor (竞品定义)
  └── Report (汇总报告)
```

### 2.3 Provider 架构

Elmo 的 Provider 层包含两类能力：

1. **AI Model Providers**（LLM 调用）：
   - `openai-api` → ChatGPT (GPT-4o, o3, etc.)
   - `anthropic-api` → Claude
   - `mistral-api` → Mistral
   - `openrouter` → 多模型聚合

2. **Web Research Providers**（浏览器爬取）：
   - `olostep`, `brightdata`, `oxylabs`, `cloro`, `dataforseo`

这与 geo-collector 的 Playwright 直连方式形成对比：Elmo 通过抽象层管理多种 Provider，可切换。

## 6. 关键差异与风险

### 6.1 风险矩阵

| 风险 | 严重性 | 可能性 | 缓解措施 |
|------|--------|--------|----------|
| Elmo 使用 PostgreSQL，本项目用 SQLite | 中 | 高 | Adapter 通过 REST API 交互，DB 类型透明 |
| Elmo 无 recommendation_level | 高 | 确定 | Measurement 层自行计算（基于 raw_output LLM 分析） |
| Elmo 无 geo_score | 高 | 确定 | Measurement 层自行计算 |
| Elmo 无 Citation 分类 | 中 | 确定 | 基于 URL domain 规则推断 |
| Elmo 无 anchor_text/context | 中 | 确定 | 标记为未知，或从 raw_output 提取 |
| Elmo 的 Prompt 无 category/intent/location | 低 | 确定 | 兼容 layer 填充默认值 |

### 6.2 架构差异

```
geo-collector:
  浏览器自动化 → 原始 HTML → answer_parser → JSON extraction → SQLite

Elmo:
  API 调用/Scraper → raw_output JSON → REST API → PostgreSQL
```

两种系统的数据提取方式不同：
- geo-collector 是浏览器自动化，能捕获 JS 渲染后的内容
- Elmo 是 API 优先（部分 Provider 走 Scraper），输出结构化 JSON

**影响：** Elmo 的 `raw_output` 已经是 JSON 结构，比 geo-collector 的 HTML 更易于解析。

## 8. 决策建议

### 8.1 推荐：继续使用 Elmo 作为 P1

**理由：**
1. ✅ 架构成熟：Drizzle ORM + PostgreSQL + pg-boss 生产级方案
2. ✅ Provider 抽象完善：API 优先 + Scraper fallback
3. ✅ MIT License：无商业限制
4. ✅ 活跃的开源社区（elmohq）
5. ✅ 核心数据模型与本项目高度对齐
6. ✅ 缺失字段可在 Measurement 层补充（这是本项目的价值所在）

### 8.2 注意事项

1. **数据库迁移**：Elmo 用 PostgreSQL，本项目用 SQLite。建议通过 REST API 交互，避免 DB 类型耦合。
2. **Recommendation 层**：Elmo 不评估推荐等级，需在 geo-distributor 的 Measurement 层基于 LLM 分析补充。
3. **Prompt 元数据**：Elmo 的 Prompt 缺少 category/intent/location，如果业务需要，需从 geo-collector 同步或手动补充。
4. **Brand 关联**：Elmo 的 Brand 属于 Organization，需处理层级关系。
