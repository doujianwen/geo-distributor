## 1. 问题与责任判断

此前把客户易理解的成果界面扩展成了统一的作业界面，又把新增长链路的十模块映射当作原内容增长系统完整性证明。这一判断不成立。总部运营不是只处理商业受理与交付的人，还需要直接做 GEO 内容运营。

核对原系统后，缺口同时存在于界面、操作适配和数据接入三个层面。不能答复为“原功能都在，只是入口换了”，也不能把新增菜单、任务卡或通过现有回归测试等同原功能已经恢复。

原系统入口位于 `E:/一人公司/独立站/geoflow/geo-intent-system/static/app.js`，有15个导航视图；原业务接口在同目录的 `app/main.py`。整合适配层 `app/portal_contract.py` 的 FIELDS / EDIT_TABLES 只支持部分对象字段及新增长链路操作，不能覆盖原生专业工作流。

以下是源码能力盘点，不是对真实采集、模型调用或历史数据可用性的运行验收。

## 3. 工作区设计

### 3.1 同一账号，按作业能力进入工作区

登录仍使用个人账号，不展示角色启动器。账号授权同时表达组织、项目范围和操作能力。

- 总部管理员：账号与授权、商业范围审批、全局管理；具备作业授权时也能进入专业作业台。
- 总部运营 / GEO优化人员：默认进入专业作业台，直接管理授权项目中的内容、问句、关键词、监测和优化工作。
- 渠道商管理员：客户与项目管理；有专业作业授权时进入同样的专业作业台。
- 客户成员：默认进入成果与协作工作区；查看与编辑合为同一身份。客户若购买自助服务并获作业授权，也可开放对应专业模块。

“GEO优化人员”是工作职责，不应机械等同某一公司身份。切换工作区只改变呈现，不改变权限。支持多种职责的账号登录后切换“专业作业 / 客户与交付”，不要求重新登录或冒用另一个角色。

### 3.2 专业作业台是主产品的一部分

专业作业台保留原名称和对象边界，可按下列组整理导航；组展开后页面直接可达，支持固定常用模块和直达链接，不把专业入口藏入客户成果页。

| 导航组 | 页面 |
|---|---|
| 今日工作 | 作业概览、待处理、到期复查 |
| 产品与研究 | 产品、用户画像、场景 |
| 问题与策略 | 问句库、关键词库、问题簇 |
| 内容生产 | 内容Brief、内容缺口、实体库、相关页面与事实资料 |
| 监测与增长 | 引用追踪与监测任务、SEO Growth、实测证据、诊断、优化行动、发布记录、复查比较 |
| 报告与资料 | 趋势报告、客户交付报告、提示词库、操作手册 |

顶部保持当前客户 → 项目 → 产品/站点的清晰上下文。只有存在经核验的绑定时才能自动选中；无绑定时进入明确的绑定流程，不能凭名称猜测或让普通运营手填内部编号。多产品、多站点的项目允许切换，范围始终可见。

原有密集列表、筛选、批量操作、预览后应用、草稿采纳等高效交互应复用并改善。任务卡用于提醒和直达，不代替模块；运营不必先等总部逐项派发任务，才能在已授权服务范围内整理问句、生成Brief或配置监测。

客户工作区继续聚焦效果、进度、建议、资料补充和报告。客户的简洁不再通过删减专业人员能力实现。

## 4. 接入与数据原则

1. 原内容增长系统继续作为唯一增长业务核心。复用原页面流程、业务服务及对象关系，在统一外壳中适配；不再按少量通用字段重建第二套简化系统。
2. 原内部接口未具备完整多租户权限，不直接公开整站、不通过无约束代理或嵌入原页来绕过授权。逐项增加受保护的业务适配：从登录身份取得项目范围，校验产品、站点及每个关联对象，防止提交外部编号跨项目操作。
3. 日常内容作业、批量操作及生成能力由明确能力授权；商业批准、账号授权、系统重置、样例导入、密钥配置另行控制。专业作业权不等于系统管理权。
4. AI功能保留人工提示词复制与回填流程；真实模型调用单独验收。收费/外部调用显示执行范围、额度与任务状态；预览、应用、失败重试与重复提交有明确语义。不能承诺尚未验证的自动采集、外部发布或定时执行。
5. 原Brief状态、历史引用检查、内容缺口继续保留原意；不自动当成新Publication、质量通过的Observation或新Diagnosis。需要互链时使用显式关系和来源，遵守已冻结的测量规则。
6. 当前新工作区库并未自动接入原全部历史产品和项目。先核验运行数据源、原产品/站点归属及门户客户/项目绑定，再制定可回退的接入方式；不能将新空库描述为原系统全量迁移。不得自动认领、改写真实历史记录或用演示案例冒充历史接入。
7. 原本地作业系统作为能力比对基线保留；新专业入口未完成保护和验收前，不宣称已经替代原系统。历史架构文档中“门户只读投影”的限制需要按本次专业操作需求修订，不能继续作为屏蔽作业的产品依据。

## 5. 按实际运营任务验收

验收必须由专业人员完成连续任务，而非只查看模块标题或对象计数。

| 任务 | 最低通过条件 |
|---|---|
| 接手已有产品 | 能找到授权的真实历史画像、场景、问句、Brief及监测关联；空白原因明确，无错误认领 |
| 整理研究问句 | 保留来源与意图，批量评分/分类可预览和选择应用，能够建立并检查问题簇关系 |
| 形成内容方案 | 问题簇进入Brief，生成结果可修改与采纳，能回溯关联问句；提示词手工流程仍可用 |
| 持续监测与优化 | 配置监测、录入/导入检查、查看趋势和缺口；运行失败可见；新实测及诊断有独立证据来源 |
| 发布后复查 | 能区分内容工作状态、真实发布记录、复查时间、SEO排名与GEO引用；不会把改状态说成已自动发布 |
| 跨项目工作 | 切换时上下文和对象关系正确；批量请求、直接接口及过期页面不能越权；错误不丢失输入 |

发布前形成“15个原页面 × 原操作 × 权限 × 数据来源 × 测试证据”的覆盖表。每项标记：已接入并通过、部分接入、未接入、仅维护用途、经批准延期。不得用“十模块可达”替代这张表；未接入的专业高频操作不得判定完整替代通过。
