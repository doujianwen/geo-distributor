现有共享接入码没有变成逐员工账户体系。授权使用服务端稳定身份指纹，访问码不下发浏览器；客户编辑身份通过现有受保护的注册渠道配置并绑定企业。

## 真实核心与可靠性证据

隔离库通过实际服务完成：

`问题 → Run/Observation/Evidence → 质量复核 → Diagnosis → Action → 批准/执行 → Publication 四快照 → 第二次 Run → 合法 Delta → 原归因 → measured/closed → 固定报告`。

测试直接断言同一核心库中的领域行、关联及状态，没有用业务待办替代 Action。

- 205 项相关回归全部通过，包括既有渠道商、客户、总部、租户隔离、路径防护与幂等回归；证据：`exports/unified-growth-20261019/tests.xml`。
- 其中 9 项独立对抗回归验证质量撤回且中途无 GET、下游结论传播、客户审批绕过、冲突历史 Delta、内部 commit 后故障回滚、SEO 证据及复核时间、绑定重试、同租户跨客户、比较条件和快照完整性。
- 多个独立 SQLite 连接并发提交同一幂等键只得到一个对象；同键不同内容和旧版本冲突；新连接重试读取持久结果。
- 原服务内部 BEGIN/commit/rollback 经事务适配：领域对象、质量事件、快照撤销、版本、操作重放和审计共同提交或回滚。注入失败后不残留部分结果。
- 已实际重启固定演练服务：浏览器新建问题仍为 1 条，测量申请仍为 1 条，被指派行动仍为 `in_progress`。虚拟核心含 2 个 Run、2 条 Observation、2 条 Evidence、1 条 Diagnosis、2 条 Action、1 条 Publication、3 条 Delta。
