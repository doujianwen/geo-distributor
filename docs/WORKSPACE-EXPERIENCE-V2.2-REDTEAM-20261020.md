## 3. 定向补充后的V2.2规则

### 3.1 资源归属与项目关系

产品/站点是增长资源，客户是其归属主体，商业项目是服务与交付容器。项目名称、站点域名都不能作为唯一身份。一个项目可关联多个已授权产品/站点；同一客户的后续项目可以继续关联原资源，避免复制历史。

产品级问句、画像、问题簇和Brief属于产品资源；站点级观测、页面和排名属于站点资源。读取或修改产品级内容，必须具有该产品的明确授权；只获得一个站点或某项目的报告权限，不获得整产品原始资料。需要项目私有内容时，先增加明确的项目范围模型，不以界面筛选模拟隔离。

不同客户之间默认禁止共享可写产品。总部模板另作模板域；复制模板生成新对象及来源记录，不共享客户业务记录。跨客户移交资源是专门的管理流程，不允许普通运营修改归属字段。

首个可交付版本可以保持“一项目一组产品/站点”，但必须在界面和验收中明确限制，不能宣称支持多资源或接入被拒绝的历史多站点产品。完整替代阶段须实现项目关联集合与站点选择；涉及原一产品多站点的数据，在所属范围校验完成前不接入，不能通过删原数据规避限制。

首期与完整替代是不同里程碑；未完成多资源能力时，按资源逐个开通试用，不扩大原绑定限制。

### 3.2 权限与账号

授权结果由“有效个人身份 × 组织成员资格 × 客户/产品/站点范围 × 操作能力 × 对象状态”共同决定。前端菜单仅展示服务端返回的能力。登录账号映射不得直接把WordPress编辑权限当总部运营权限。

| 能力类别 | 默认规则 |
|---|---|
| 查看客户成果/报告 | 按客户、项目及发布状态授权；不带出专业字段 |
| 内容研究与编辑 | 获产品/站点作业授权的优化人员可直接操作，不强制逐项总部派单 |
| 批量导入/生成/监测 | 在相应资源写权限之上增加批量/调用能力、限额和审计 |
| 商业范围/账号授权 | 总部管理明确授权；日常编辑不允许扩大范围 |
| 证据质量处置 | 单独能力；需要复核的证据不得由提交者自行放行 |
| 报告对外发布/撤回 | 单独能力；不能由“可以写Brief”自动推导 |
| 外部网站发布 | 首期若无已验证连接器，只登记真实发布；未来连接器另设权限和目标核验 |
| 系统重置/种子数据/密钥 | 维护能力，不进入普通专业菜单 |

总部运营默认仅见分配资源；全客户读取为明确授予的额外能力。总部管理也不因管理身份自动获得所有内容写入权。客户编辑/查看合并只改变身份呈现，不取消只读能力配置。

授权撤销、客户停用、项目或绑定变更后：下一次读取、提交、队列执行均重新校验；浏览器会话、下载链接与缓存不得继续提供撤权后的新访问。已有下载文件无法远程收回，界面不能作相反承诺。会话桥接需覆盖过期、CSRF防护及退出；浏览器不持有服务端密钥。

### 3.3 历史数据接入

接入记录至少含：环境、实际数据库路径/标识、数据库备份与schema版本、原对象ID、来源系统、客户归属、产品/站点关系、项目关联、冲突及批准记录。数据内容不写入公开审计文档。

顺序：只读盘点 → 归属候选与人工核验 → 冲突隔离 → 在备份副本中预演 → 核对数量与关键关系 → 批准接入窗口 → 接入 → 读写与回退验证。副本只用于预演，不成为长期并行业务真相库。

优先采用经治理的权威数据源及显式关系；若必须迁移，保留来源ID映射和校验记录，禁止凭名称合并，禁止用样例填补空缺。无法确认归属的对象不公开给任何客户，不因此阻塞已确认资源的有限试用。原真实记录的迁移或归属变更应作为可审阅批次，按既有授权门禁执行。

### 3.4 单一权威写入路径

复用原业务服务，但所有已接入对象域的写入均通过同一授权、版本、事件和失效处理边界。后台任务、脚本、旧页面同样遵守；不能只保护新门户按钮。

按对象域切换：未接入域继续在受控原环境作业，门户显示“尚未接入”；已接入域停止绕过新边界的旧写入口，旧界面若继续使用必须改接同一受保护命令。不得在同一资源上保留两个无协调写入口，也不得承诺原HTTP可直接开放给客户。

因此修正V2.1“保留原系统”的含义：保留代码、备份、历史与能力基线；是否允许继续写，由该资源的切换状态决定。

### 3.5 外部调用与任务执行

数据库事务不包裹长时间外部调用。任务先持久化授权范围、调用参数摘要、输入版本、幂等键和额度预约，再由执行器领取；执行前复核身份/授权和资源版本，完成后在短事务中登记结果。任务状态至少区分排队、执行、成功、失败、结果未知、取消请求、已取消；已发出的请求不能保证停止收费。

仅在提供方支持时承诺请求级幂等。超时但无法确认结果时进入“结果未知”，不得自动反复调用；人工核对或明确再次发起，记录可能的额外费用。预览应用只作用于预览时的对象版本；源数据变化后重新预览。定时监测是否存在可运行执行器必须验证，配置频率不等于已定时执行。

### 3.6 原功能覆盖表

15页面是入口基线，不是能力总数。实施必须登记每个页面动作、服务端路由、后台作业/导入脚本、批量与导出、前置条件、对象关系、权限、数据来源、状态变化、副作用、测试证据及替代入口。

分类：原能力保留、原能力受控改造、维护专用、新增能力、经批准延期。源码中按钮/路由存在不等于运行可用；分别记录“源码存在/适配完成/隔离运行通过/真实连接验证”。不为追求逐行复制而恢复旧缺陷；原工作任务不得无说明丢失。

### 3.7 并发、批量与上下文

对象编辑使用对象版本；涉及关系集合/配额的命令另校验对应集合或依赖版本。站点级总版本可暂作保守防护，不作为多用户专业作业的最终协作机制。同对象冲突展示差异，保留输入，不静默最后写入覆盖。

批量操作必须声明提交语义。关系变更等需要一致性的命令原子提交；独立导入项可逐项提交，但必须返回逐项结果、成功ID、失败原因、幂等键与批次记录。预览展示增改删数量和异常；重试成功项不重复写入。不得用一个无限长事务包住所有外部生成。

路由及请求明确携带资源上下文，不依赖全局state猜测。切换资源后，旧响应不覆盖当前页；旧编辑保存前核对上下文并提示，不能改写成新项目。浏览器缓存、筛选状态、草稿和多标签页按用户及资源隔离。

### 3.8 删除、版本与证据

先定义对象依赖图：问句—簇—Brief—监测/引用，以及产品/站点—页面/事实—观测—诊断—行动—发布—比较/报告。存在引用的对象优先归档；禁止静默级联删除证据或历史交付物。需要更正时保存原记录及替代关联，不覆盖原实测事实。

每类变更明确其影响：例如问句修改产生新版本，不能把旧回答当作新问题结果；事实变化使依赖旧事实的草稿待复核；证据撤销/质量变化使依赖结论和报告有效性重新计算。不可变报告快照保留当时版本，当前有效/撤回/待复核单独显示。新旧趋势保持各自口径，未知与零值分开。

模型发送、导出、报告与搜索均按字段与范围授权。业务提示词可对获授权专业人员开放，内部系统模板、服务商密钥、其他客户案例不随之开放；输入材料的模型发送范围需可见并符合项目配置。

### 3.9 体验与规模

专业首页以待处理和继续作业为主，允许直接进入模块；保留原名称、固定常用模块、上下文关联跳转。高级字段按任务展开，默认值来自可信上下文。权限不足、未接入、空数据、加载失败和会话失效分别说明，不伪装成“暂无”。

列表采用服务端分页、筛选和范围校验；跨全库汇总设限，不在浏览器读取全量再隐藏。验收数据规模和响应时间目标须在实施初始冻结并记录，不能用5条示例证明真实规模可用。首轮至少用1,000条问句与100项批量任务的隔离数据验证分页、筛选、重试与结果完整性；此数为验收下限，不是容量承诺。

1440/768/390视口验证导航、查看与轻量编辑；复杂批量操作可明确要求桌面，不假装手机完成同样密集任务。键盘可完成选择、提交、纠错和返回；焦点、确认及状态通知清楚。实际GEO优化人员参加连续任务走查，记录卡点，不以主审扮演客户代替真实试用。

### 3.10 发布与回退

试用按人员、资源和对象域开通。切换前记录数据库与schema版本、写入入口、未完成任务和审计基线；切换后核对核心关系与新增记录。回退先停新写及新任务，再确认兼容读取与数据对账。

仅界面问题且新数据兼容时可回退界面；schema/数据不兼容时采用修复或经核验的迁移回退，不简单把备份覆盖在线库。未完成外部任务需单独处理，回滚数据库不能撤销对外请求。生产门禁仍以既有流程为准，本文件不解除BLOCKED状态。

## 4. 第二轮场景复核

复核方法：不再按页面看方案，改用能使方案失败的操作序列。以下为桌面推演，未运行接口，不声称独立。

| 场景 | V2.1缺口 | V2.2规则结果 | 实施证据门槛 |
|---|---|---|---|
| 一个项目第二个站点；同一产品跨两个站点 | 设计承诺与schema冲突 | 首期限制明确；完整替代必须关系集合及产品权限 | 真实关系fixture及授权测试 |
| 同客户另一个项目引用产品；不同客户请求同产品 | 仅项目过滤无法定义共享 | 关联不赋权；产品原始数据需明确产品授权 | 正反向读取、编辑、导出测试 |
| 渠道优化员开通专业权；普通HQ运营请求未分配客户 | role写死 | 按能力和范围分别允许/拒绝 | 同一身份能力变化回归 |
| 撤权发生在任务排队后、执行前 | 初次授权不足 | 执行前再校验；取消与费用边界可见 | 可控执行器测试与审计记录 |
| 外部调用成功但响应丢失，用户点击重试 | 重复费用 | 结果未知，不自动重新调用 | 模拟提供方超时/回执重放 |
| 两人编辑不同问句；两人编辑同一问句 | 总版本过度冲突 | 对象并发分别处理 | 并发冲突及输入保留测试 |
| 批量100条含无权限项；成功后重复提交 | 失败语义不明 | 声明原子/逐项，结果和重试可追溯 | 部分失败、幂等及越权项测试 |
| 切换项目时旧请求返回或旧编辑保存 | 全局state竞态 | 明确上下文与旧响应抑制 | 浏览器竞态及直接接口测试 |
| 旧后台改已引用问句，新报告继续展示 | 绕过失效 | 同一写边界、版本链与有效性处理 | 旧入口/脚本绕行负向测试 |
| 删除被引用Brief；撤销证据；恢复旧版 | 删除、失效、回退无定义 | 归档/更正、依赖复核、兼容性回退 | 引用与快照保留、回退对账 |
| 模板复制/报告导出夹带其他客户内容 | 单纯页面权限不足 | 模板来源与字段范围检查 | 模型请求载荷与导出内容检查 |
| 数据源暂不可用；真实历史尚未绑定 | 被误读无数据 | 状态分别呈现，不生成样例冒充 | 空/错/未绑定/失效四类展示 |

第二轮追加修正已并入上文：①项目关联不赋予产品权限；②已下载内容不能远程撤回；③任务取消不承诺撤销已发生费用；④首期受限试用不等于完整替代；⑤单一写入按对象域切换，不能全站一刀切阻塞未接入运营。

复核结论：上述设计矛盾已有明确规则；所有运行结果仍待实现验证。独立复核门槛仍未满足。

## 6. 唯一正式执行指令（V2.2）

本节是后续实施的统一要求，本轮审计不自动执行开发或真实迁移。

1. 冻结当前代码/数据源/写入口清单、原功能操作矩阵及资源关系。先登记未知项，不以假定归属填空；确定首期试用与完整替代的不同范围。
2. 实现可信个人身份到能力与资源范围的服务端边界，保留既有租户和路径防护。逐项覆盖读写、导出、后台任务、撤权及客户停用；完成负向测试后再开放新写入口。
3. 在隔离副本预演历史归属与绑定方案，修订资源关联和旧只读ADR；实际迁移/认领形成单独可审阅批次。演示数据只在清晰标记的隔离环境使用。
4. 按对象域复用原专业页面流程和业务服务，接入同一写边界；先恢复高频连续任务，保留原模块直达、批量、生成、采纳和监测操作。未接入明确标记，不删除原能力基线。
5. 补齐对象并发、批量语义、任务执行、成本控制、依赖失效、归档与审计。外部连接未经验证时只提供真实可用的人工流程，不展示虚假自动化状态。
6. 客户成果与专业作业采用不同投影及交互，共用授权后的事实。专业授权可授予符合条件的渠道/客户人员；管理、质量处置、报告发布、外部发布权分别配置。
7. 对照第7节逐项验收，取得实际优化人员任务走查证据，完成独立审计并处理其发现；仍有关键未接入能力时仅批准明确范围的试用，不宣布完整替代。
8. 通过有限试用与回退演练后形成可部署包；生产继续遵守现有门禁。报告列明已接入、受限、延期和未验证内容，不以旧205项回归数替代本轮证据。

禁止另起增长核心、无约束转发原内部API、自动改写历史事实、无协调双写、全局HQ角色替代项目授权、把模型超时当安全重试、用纯菜单检查判定运营完整性。
