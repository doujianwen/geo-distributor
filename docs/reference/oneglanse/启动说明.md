# OneGlanse 本地启动说明

> 系统位置：`E:\GEO项目\技术层\GEO海外分销系统\oneglanse`
> 说明更新：2026-09-12

---

## 一、怎么启动（就一步）

双击项目根目录下的：

```
启动OneGlanse.bat
```

脚本会自动完成 6 步，全程约 30 秒（前提是依赖和镜像已就绪）：

| 步骤 | 动作 |
|------|------|
| 1 | 检查 Node.js 与 pnpm |
| 2 | 读取 `.env` |
| 3 | 检查 Docker，未运行则自动拉起 Docker Desktop 并等待 |
| 4 | 启动 postgres / clickhouse / redis 三个容器 |
| 5 | 执行数据库迁移 |
| 6 | 各开一个新窗口启动 web 与 agent |

启动完成后自动打开浏览器，访问地址：

- 前台界面：**http://127.0.0.1:3000**
- Agent API：http://127.0.0.1:3333

> 首屏第一次访问需要现编译，等 20～60 秒出页面属正常。

## 二、怎么停止

关闭 `web` 和 `agent` 那两个黑窗口即可。

若窗口已丢，用任务管理器结束残留的 `node.exe`，或执行：

```powershell
docker compose -f "E:\GEO项目\技术层\GEO海外分销系统\oneglanse\docker-compose.yml" stop
```

## 三、文件说明

| 文件 | 作用 |
|------|------|
| `启动OneGlanse.bat` | 入口，双击即可（纯 ASCII，避免中文编码问题） |
| `oneglanse\scripts\start-oneglanse.ps1` | 主逻辑，UTF-8 **带 BOM** 保存（PowerShell 5.1 必需） |
| `oneglanse\scripts\run-service.mjs` | 单个服务的运行器，负责装配 `.env` 环境变量后前台运行 |

`run-service.mjs` 存在的意义：官方入口 `run-local.mjs` 把 web/agent 当作自己的子进程，
父进程一被回收两个服务一起死；这里改成"一个窗口一个服务"，互不牵连，日志也直接打在窗口里。

## 四、启动前已为你修好的问题（历史记录）

| 问题现象 | 根因 | 处理 |
|---|---|---|
| `EPERM: operation not permitted, symlink 'E:\...\.pnpm-store'` | pnpm store 落在盘根目录，普通用户无权建符号链接 | `pnpm config set store-dir` 改到 `C:\Users\29537\.pnpm-store` |
| `DATABASE_URL is not defined` | Next.js 从 `apps/web/` 启动，读不到仓库根目录的 `.env` | 由 `run-service.mjs` 显式注入；另建了 `apps/web/.env` 软链 |
| `apps/web/node_modules/next` 缺失 | pnpm 未在 app 目录创建链接 | 已补建指向根 `node_modules/next` 的链接 |
| 健康检查超时、启动脚本误判失败 | Node 22 把 `localhost` 解析成 IPv6 `::1`，而 Next 只监听 IPv4；且首屏编译约 72 秒 > 原 60 秒超时 | `run-local.mjs` 已改为 `127.0.0.1` 且超时放宽到 120 秒 |
| Docker Hub 连不上导致启动失败 | 编排脚本用 `--pull always` + `--build`，强制联网重拉 | 已改为 `--pull missing` 且不再重建镜像，走本地缓存 |
| `start-oneglanse.ps1` 一闪而过、满屏红色报错 | PowerShell 5.1 把「UTF-8 无 BOM」的中文脚本按 GBK 解析，语法直接崩 | 脚本改为 UTF-8 **带 BOM** 保存 |

## 五、为什么不能在 WorkBuddy 对话里直接帮你启动

WorkBuddy 的沙箱有两个硬约束，导致长驻服务无法在其中存活：

1. 每次工具调用结束后，该调用产生的**整棵进程树会被回收**（`nohup`、`Start-Process`、
   计划任务都试过，一样被回收）。
2. 沙箱对进程内存有上限。Next.js 的 dev server 在编译路由时要申请大块内存缓冲，
   会以 `RangeError: Array buffer allocation failed` 失败，随后整个 server 优雅退出（exit code 0）。

**这两个约束只存在于 WorkBuddy 会话内，你自己双击运行的窗口完全不受影响。**

## 六、排错

**窗口里出现红色报错怎么办？**
把报错原文发我即可，同时附上：

```
oneglanse\.local-logs\web.log
oneglanse\.local-logs\agent.log
```

**端口被占用？**
```powershell
netstat -ano | findstr :3000
taskkill /PID <上面查到的PID> /F
```

**内存偏紧？**
本机 16GB，实测启动前仅剩约 2.4GB 空闲（WSL/Docker 占 2.1GB，浏览器多开占 2GB+）。
如果 web 窗口反复崩，先关掉部分浏览器标签，并停掉不用的容器后再启动。

**想用官方原生命令启动？**
官方入口同样可用（已打上上面提到的兼容补丁），在终端执行：

```powershell
cd "E:\GEO项目\技术层\GEO海外分销系统\oneglanse"
pnpm local
```
