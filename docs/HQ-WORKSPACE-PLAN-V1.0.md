# 总部管理员与运营后台体验优化规划 V1.0

2026-10-19。现行规划，已完成审查、实施和本机验收。唯一执行指令为 [HQ-WORKSPACE-EXECUTION-20261019.md](HQ-WORKSPACE-EXECUTION-20261019.md)，不再保留并行待执行版本。

## 目标与角色

让总部从同一工作区完成：**接收线索 → 分配或直管建档 → 受理需求 → 确认服务范围 → 管理批准 → 推进交付 → 生成报告 → 明确向客户发布 → 处理客户反馈**。

沿用现有两种能力身份：HQ_TECHNICAL 为总部运营/技术；HQ_MANAGEMENT 为总部管理。它们仍是集成身份，不能据此声称具备逐员工账户与审计体系。

| 能力 | 运营 / 技术 | 总部管理 |
|---|---|---|
| 查看全渠道或所选渠道业务 | 可以 | 可以 |
| 人工分配线索与建档、线索转需求 | 可以 | 可以 |
| 要求补充、拟定并保存范围 | 可以 | 可以 |
| 批准或拒绝需求 | 不可以 | 可以 |
| 补充普通渠道需求 | 不可以，由所属渠道管理员办理 | 同左 |
| 补充总部直管需求 | 可以，说明线下核实内容 | 可以 |
| 启动、推进/完成阶段、登记/解除阻塞 | 可以，受状态与版本守卫 | 可以，受相同守卫 |
| 生成技术报告、审查发布/撤回、处理客户反馈 | 可以，沿用既有QA与授权 | 可以，沿用既有QA与授权 |

所有能力由服务端执行，界面隐藏不作为授权控制。

## 页面结构

采用蓝白工作区，桌面侧栏与手机折叠菜单。总部使用专用入口 `/ui/hq/`，官网为 `/portal/hq/`；旧渠道入口登录总部身份仍可进入相应导航。

| 栏目 | 用户任务 |
|---|---|
| 总部工作台 | 八类待办分别计数，显示范围与读取时间，点击进入完整队列；受阻与待启动项目优先展示 |
| 线索分配 | 搜索线索，查看联系人、网站、原始需求与来源；从已注册渠道下拉选择接收方或总部直管，确认对象后建档，再转待确认需求 |
| 需求受理 | 搜索与状态筛选，查看客户和渠道、补充资料、保存范围和周期、由管理批准或拒绝；批准前没有正式项目 |
| 项目交付 | 跨渠道查看客户、状态、四阶段、阻塞与更新时间；进入GEO依据、报告与客户协作；操作前明确客户与当前阶段 |
| 客户与渠道 | 查询客户档案及所属渠道，进入关联需求/项目/GEO结果；渠道业务汇总区分可分配的注册渠道和只供历史查询的业务归属 |
| 结果与反馈 | 搜索历史报告、核对客户可见性、进入项目办理发布；区分客户未答、已答待团队处理与已关闭/撤回 |
| 操作记录 | 查询已存储的线索、需求、交付操作、发布和协作事件，提供对象入口；未知角色/时间不补造，不宣称是完整安全日志 |

全局范围默认“全部渠道与总部直管”，可选择已有渠道。列表在完整搜索与筛选后分页，每页20条；返回详情保留搜索、筛选和页码。总部待分配线索归于 HQ-INTAKE，选择某渠道后不会冒称该渠道有全局待分配工作量。客户名称按渠道与客户共同匹配，详情链接保留归属。

## 待办与状态口径

| 卡片 | 事实口径 |
|---|---|
| 待分配线索 | new 与 pending_assignment，二者都能从卡片进入 |
| 待拟服务范围 | submitted / intake_review / scoping，不包括等待渠道补充 |
| 待管理批准 | scope_pending_approval |
| 受阻项目 | blocked；不以某条失败测量自动判定整个项目受阻 |
| 待客户回复 | 协作记录 pending |
| 客户已答 · 待团队处理 | submitted / confirmed / changes_requested |
| 报告待审查与发布 | 尚无发布授权的客户安全报告；此计数不代表已通过QA |
| 客户发布已失效 | 曾发布但原报告/测量关联或内容指纹已变化、原报告缺失；已撤回不算失效异常 |

报告分别显示：尚未发布、客户当前可见、已撤回、发布已失效、内部报告。客户停用或档案缺失时，即使发布授权仍有效，也显示“发布有效 · 客户访问已停用或档案缺失”。读取故障不折算成零待办；完成阶段、报告生成、客户意见和项目验收保持独立。

## 关键交互与业务闭环

**分配与受理：** 分配前确认客户和目标渠道；同一分配重试返回原客户与关联，变更内容冲突，不能重复建档或任意改派。总部直管也进入同一审批流程；直管要求补充后总部可记录核实结果，普通渠道需求仍由所属渠道管理员补充。

**范围与批准：** 保存范围、周期、交付物和排除项；编辑未保存时禁用批准，失败保留输入，离开需确认。批准使用需求revision；旧页面冲突不覆盖他人结果。已批准范围冻结，变化继续新需求，不自动产生报价。

**交付：** 项目启动、推进/完成阶段及阻塞恢复均携带当前版本与幂等编号。受阻先恢复，末阶段不能继续推进；阻塞需原因、行动与处理方，恢复需说明。项目与处理事件一次事务写入。本入口不接受手工填写测量、报告或发现编号，产出继续由原交付链路登记。旧start/stage/complete API同样要求版本与幂等编号；缺失返回422提示刷新。

**报告与客户协作：** 复用既有测量、交付与scope版本幂等。生成报告与向客户发布使用不同操作；重复生成说明返回原报告，QA失败和无数据明确显示。只有现有QA与完整来源指纹通过的发布版本可进入客户后台；撤回或源变更立即影响客户读取。客户意见进入待团队处理，处理说明与历史保留，不自动验收项目。

**异常和访问：** 总部会话逐次重验凭据，撤销、降级或重绑后失效；总部入口使用独立cookie，可与渠道和客户同时登录。401保留目标并重新登录，503保留导航与重试，409保留输入并明确要求刷新；较慢的旧请求不能覆盖新路由。密钥不进入浏览器存储或业务响应。
