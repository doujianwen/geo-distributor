## 实施要点

- 新增个人身份交接与总部开通界面：WordPress 保管密码，工作区接收短时签名身份，单次票据换服务端会话。未配置时明确显示未开通。正常登录页不罗列角色；演练入口的角色按钮只服务虚拟验收。
- 项目/产品/站点显式绑定，每组资源独立授权；新增资源不继承旧资源授权。总部运营也需要资源授权。保存撤权不再回退旧编辑授权。
- 所有原生命令经同一个受保护入口；检查当前商业状态、个人会话、成员资格、所选资源和嵌套引用。请求幂等持久化，旧对象版本冲突拒绝；不同对象可分别编辑。
- 短命令以身份库→商业库→核心事务的固定顺序锁定。项目停止或成员撤销后的命令拒绝；不在锁内执行外部任务。真实专业写入默认拒绝集成服务账号。
- 客户投影过滤原始回答及内部证据内容。只读请求不提交写事务；研究作者不能自行质量复核。
- 主要业务列表使用 SQL 搜索、计数和分页，每页 20 条、上限 100 条；部分旧关联选择器仍有 2,000 条显式容量限制，超限报错而不静默截断。监测来源选择器已分页。该边界不算无限规模支持。
- 保存失败保留输入；服务器错误或结果不明时保留操作标识，重试复用。冲突需保留资料并刷新核对。加载时清除旧模块操作区，迟到请求不能覆盖新页面。
- 原生界面置于受限同源宿主框架，消息校验来源及随机通道，框架不持有凭据、不允许网络直连或同源身份。
